## 每日摘要流水账与总账记录功能分析



该功能位于 `agentscope-harness` 模块中，实现了一套经典的**两层记忆架构**，用于 Agent 长期记忆的自动提取、持久化和整合。

### 1\. 架构总览



```Plain Text
对话消息 (Messages)
       │
       ▼
┌──────────────────────────┐
│  MemoryFlushMiddleware   │  ← 每次 Agent 调用后触发
│  (节流/隔离控制)          │
└──────────┬───────────────┘
           │ LLM 提取
           ▼
┌──────────────────────────────────────────┐
│  Layer 1: 每日流水账 (Daily Ledger)       │

                   ▼
┌──────────────────────────────────────────┐
│  Layer 2: 总账 (Curated MEMORY.md)       │
│  MEMORY.md                               │  ← 去重、裁剪、大小受限
│  所有者: MemoryConsolidator              │
└──────────────────────────────────────────┘
```

### 2\. 核心组件详解



#### 2\.1 \[MemoryFlushManager\]\(file:///C:/workspace/opensources/agentscope\-java\-2\.0/agentscope\-harness/src/main/java/io/agentscope/harness/agent/memory/MemoryFlushManager\.java\) — 流水账管理器



**职责**: 第一层的所有者，负责从对话窗口中提取长期记忆并追加到当天的日记账文件。



**核心流程** \(`flushMemories()` 方法, L115\-L184\):

1. **序列化对话**: 将 USER/ASSISTANT/TOOL 消息渲染为文本（跳过 SYSTEM 和内部上下文消息）

2. **读取已有上下文**: 读取 `MEMORY.md`（只读参考）和当天流水账的已有内容

3. **LLM 提取**: 构造 SYSTEM\+USER 消息对发给 LLM，指导其提取新记忆、避免重复已有内容

4. **写入流水账**: 将提取结果以 `## Memory Flush — {ISO时间戳}` 格式追加到 `memory/YYYY-MM-DD.md`

    

**关键设计**:

- **追加只写 \(append\-only\)**: 不修改已有条目，保证审计安全

- **不触碰 MEMORY\.md**: 总账由 MemoryConsolidator 独立维护

- 工具调用结果截断至 1000 字符，工具输入截断至 500 字符，防止 token 爆炸

    

---



#### 2\.2 \[MemoryConsolidator\]\(file:///C:/workspace/opensources/agentscope\-java\-2\.0/agentscope\-harness/src/main/java/io/agentscope/harness/agent/memory/MemoryConsolidator\.java\) — 总账合并器



**职责**: 第二层的所有者，定期将流水账合并到 `MEMORY.md`。



**核心流程** \(`consolidate()` 方法, L156\-L220\):

1. **读取水位线 \(watermark\)**: 获取上次成功合并的时间戳

2. **增量读取**: 只读取水位线之后修改过的流水账文件

3. **LLM 合并**: 将当前 `MEMORY.md` \+ 新流水账条目发给 LLM，进行去重、合并、裁剪

4. **覆写 MEMORY\.md**: 用 LLM 输出覆盖整个文件

5. **推进水位线**: 记录本次合并时间点

    

**水位线机制**:

- 状态文件: `memory/.consolidation_state`

- 支持分布式存储 \(`BaseStore`\)，使用 CAS（Compare\-And\-Swap）最多重试 5 次

- 文件系统回退: 当 store 不可用时回退到本地文件

    

**Token 控制**: 默认 4000 tokens 上限（约 16000 字符），通过 `consolidationMaxTokens` 配置

#### 2\.3 \[MemorySaveTool\]\(file:///C:/workspace/opensources/agentscope\-java\-2\.0/agentscope\-harness/src/main/java/io/agentscope/harness/agent/tool/MemorySaveTool\.java\) — 主动记忆保存工具



**职责**: Agent 可主动调用的工具，**同时更新** `MEMORY.md` 和当天流水账。



```Java
@Tool(name = "memory_save", ...)
public String memorySave(RuntimeContext rc, @ToolParam String content)
```



- 追加到 `MEMORY.md`（即时生效）

- 追加到 `memory/YYYY-MM-DD.md`（带 `## Memory Save — {时间戳}` 标题）

- 统计 bullet 数量并返回确认信息

    

**设计意义**: 这是 Agent 写入长期记忆的**唯一授权入口**，防止 LLM 用 `write_file`/`edit_file` 随意操作记忆文件。

#### 2\.4 \[MemoryConfig\]\(file:///C:/workspace/opensources/agentscope\-java\-2\.0/agentscope\-harness/src/main/java/io/agentscope/harness/agent/memory/MemoryConfig\.java\) — 统一配置

### 3\. 中间件层



#### \[MemoryFlushMiddleware\]\(file:///C:/workspace/opensources/agentscope\-java\-2\.0/agentscope\-harness/src/main/java/io/agentscope/harness/agent/middleware/MemoryFlushMiddleware\.java\)

- 在 `onAgent()` 的 `concatWith` 阶段（Agent 调用完成后）异步触发内存刷写

- 使用 `PeriodicGate` 按隔离维度（USER/SESSION/AGENT/GLOBAL）进行节流

- 错误不会中断主流程（`onErrorResume` → 记录警告后静默）

    

#### \[MemoryMaintenanceMiddleware\]\(file:///C:/workspace/opensources/agentscope\-java\-2\.0/agentscope\-harness/src/main/java/io/agentscope/harness/agent/middleware/MemoryMaintenanceMiddleware\.java\)

- 在 Flush 之后执行，受最小间隔节流（默认 30 分钟）

- 三步维护:

    1. **归档过期流水账**: 超过 90 天的 `memory/YYYY-MM-DD.md` 移入 `memory/archive/`

    2. **运行 LLM 合并**: 调用 `MemoryConsolidator.consolidate()`

    3. **修剪旧会话日志**: 删除超过 180 天的 JSONL 文件

### 4\. 完整数据流



```Plain Text
Agent 调用完成
  │
  ├─① MemoryFlushMiddleware.onAgent()
  │     └─ doFlush() → shouldFlushNow()?
  │           ├─ ALWAYS → 总是执行
  │           ├─ NEVER  → 跳过
  │           └─ THROTTLED → PeriodicGate.tryClaim()
  │     │
  │     └─ MemoryFlushManager.flushMemories()
  │           ├─ 读取 MEMORY.md (只读)
  │           ├─ 读取今日流水账 (只读)
  │           ├─ LLM 提取新记忆
  │           └─ 追加 → memory/YYYY-MM-DD.md
  │
  ├─② MemoryMaintenanceMiddleware.onAgent()
  │     └─ PeriodicGate.tryClaim(minGap=30min)?
  │           ├─ expireDailyFiles()  → memory/archive/
  │           ├─ consolidateMemory() → MemoryConsolidator.consolidate()
  │           │     ├─ 读取水位线后的流水账
  │           │     ├─ LLM 合并去重
  │           │     ├─ 覆写 MEMORY.md
  │           │     └─ 推进水位线
  │           └─ pruneOldSessions() → 删除旧 JSONL
  │
  └─③ Agent 主动调用 memory_save 工具
        ├─ 追加 → MEMORY.md
        └─ 追加 → memory/YYYY-MM-DD.md
```

### 6\. 关键设计亮点



|设计点|说明|
|---|---|
|**两层分离**|流水账追加只写（快速、安全），总账定期合并（精确、紧凑），职责清晰|
|**增量处理**|通过 watermark 水位线机制，只处理上次合并后修改的流水账，节省 token|
|**分布式安全**|水位线支持 `BaseStore` CAS 重试，适配多实例部署|
|**细粒度隔离**|节流窗口按 USER/SESSION/AGENT/GLOBAL 隔离，防止并发竞争|
|**LLM 去重**|提取和合并阶段都向 LLM 提供已有内容，实现智能去重|
|**模型可替换**|记忆操作可配置独立的轻量模型，降低成本|
|**容错设计**|所有异步操作都有 `onErrorResume`，记忆失败不影响主对话|
